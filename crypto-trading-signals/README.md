# 규칙 기반 자동 암호화폐 투자 시스템

시세를 자주 보지 않고, 뉴스에 반응하지 않고, 객관적 규칙만으로 BTC/ETH/XRP/SOL에
투자하기 위한 시스템입니다. 감정이 개입할 여지를 구조적으로 제거하는 것이 목표입니다.

---

## 설계 철학

### 1. 자주 보지 않는 것이 전략의 일부다
일간 가격은 정보보다 잡음이 훨씬 많습니다. 자주 볼수록 잡음을 신호로 착각하고,
거래가 늘고, 수수료와 실수가 쌓입니다.

이 시스템은 **월 1회만 작동합니다.** 리밸런싱일이 아닌 날에 실행하면
시그널을 계산조차 하지 않고 이렇게만 답합니다:

```
오늘은 거래일이 아닙니다.  아무것도 하지 마세요.
다음 리밸런싱: 2026-11-01  (13일 후)
```

볼 수 없으면 흔들릴 수도 없습니다.

### 2. 증거가 있는 규칙만 쓴다
여러 자산군에서 수십 년간 살아남은 이례현상은 사실상 **추세추종(시계열 모멘텀)** 하나입니다.
RSI·스토캐스틱·MACD 같은 단기 오실레이터는 신호를 많이 만들어내지만
과최적화에 취약하고 표본 외에서 대부분 무너집니다. 그래서 쓰지 않습니다.

### 3. 진입 시점보다 포지션 크기가 중요하다
수익률의 대부분은 "언제 샀는가"가 아니라 "얼마나 크게 들고 있었는가"에서 나옵니다.
변동성이 2배가 되면 비중을 자동으로 절반으로 줄입니다. 공포에 던질 일이 없어집니다.

### 4. 뉴스를 보지 않는다
뉴스 기반 대응은 정보 우위가 없는 쪽이 항상 늦습니다.
가격 자체가 모든 뉴스의 요약본이며, 추세 필터가 그 요약을 읽습니다.

---

## 규칙

`systematic/config.py` 한 파일에 모든 판단 기준이 미리 적혀 있습니다.

| 단계 | 규칙 | 목적 |
|---|---|---|
| 1. 보유 자격 | 가격 > 200일 이동평균, 3일 연속 | 하락 추세 회피 |
| 2. 절대 모멘텀 | 3/6/12개월 가중 수익률 > 0 | 추세 방향 확인 |
| 3. 포지션 크기 | 역변동성 가중 + 공분산 기반 변동성 타겟팅 (연 40%) | 리스크 균등화 |
| 4. 상한 | 총 투자비중 ≤ 100% (레버리지 금지), 종목당 ≤ 50% | 파산 방지 |
| 5. 거래 밴드 | 목표와 5%p 이상 벌어질 때만 거래 | 수수료 절약 |

조건을 만족하는 자산이 없으면 **전액 현금(스테이블코인)** 입니다.
이 규칙은 폭락장에서 자동으로 빠져나오게 만듭니다.

## 설치

```bash
cd crypto-trading-signals
pip install -r requirements.txt
```

데이터는 Binance 공개 API를 씁니다. **API 키가 필요 없고**, 전체 히스토리를 제공하며,
한 번 받은 데이터는 `data_cache/`에 저장되어 재다운로드하지 않습니다.

---

## 1단계: 먼저 검증한다

규칙은 믿는 게 아니라 검증하는 것입니다. 실제 돈을 넣기 전에 반드시 돌려보세요.

```bash
python run_backtest.py
```

전략을 BTC 단순보유, 동일비중 보유, 적립식 DCA와 나란히 비교해
CAGR·변동성·샤프·**최대낙폭(MDD)**·칼마·연간 거래횟수를 보여줍니다.

### 과최적화를 스스로 점검하는 법

파라미터를 조금 바꿔도 결과가 비슷해야 신뢰할 수 있는 규칙입니다.

```bash
python run_backtest.py --ma 150
python run_backtest.py --ma 250
python run_backtest.py --vol-target 0.30
python run_backtest.py --start 2021-01-01   # 다른 구간에서도 되는가
```

MA 150에서 좋고 200에서 나쁘다면, 그건 전략이 아니라 **우연**입니다.
"가장 좋은 숫자"를 찾아 헤매는 순간 백테스트는 거짓말을 시작합니다.

## 2단계: 보유 현황 등록

```bash
python run_rebalance.py
```

첫 실행 시 `holdings.json`이 생성됩니다. 실제 보유 수량과 현금을 입력하세요.

```json
{
  "cash_usd": 10000.0,
  "units": { "BTC": 0.0, "ETH": 0.0, "XRP": 0.0, "SOL": 0.0 }
}
```

이 파일은 `.gitignore`에 등록되어 있어 커밋되지 않습니다.

---

## 3단계: 자동화

매일 실행되게 걸어두되, 실제로 무언가 하는 날은 한 달에 하루뿐입니다.

```bash
crontab -e
```

```cron
# 매일 09:05에 점검 (거래일이 아니면 "아무것도 하지 마세요"만 출력)
5 9 * * * cd /path/to/crypto-trading-signals && /usr/bin/python3 run_rebalance.py >> cron.log 2>&1
```

리밸런싱일에는 이런 주문표가 나옵니다:

```
     실행할 주문
 자산   구분   수량        금액        현재비중  목표비중
 BTC    매수   0.043210    $4,512.30    28.4%    40.1%
 SOL    매도   12.500000   $1,840.00    16.3%     0.0%
```

거래소에서 실행한 뒤 `holdings.json`을 갱신하면 됩니다
(`--dry-run` 없이 실행하면 목표 상태로 자동 기록됩니다).

### 거래일이 아닌데 궁금할 때

```bash
python run_rebalance.py --force
```

규칙 판정표는 보여주지만 **주문은 출력하지 않습니다.** 의도적인 제약입니다.

---

## 주문까지 완전 자동화하려면

지금 시스템은 **주문표까지만** 만들고 체결은 사람이 합니다. 의도한 기본값입니다.
거래소 API로 실제 주문까지 자동화하려면 최소한 다음을 지켜야 합니다:

1. **출금 권한은 반드시 끈다.** 거래 권한만 부여합니다. 키가 유출돼도 자산은 못 빼갑니다.
2. **IP 화이트리스트**를 건다.
3. **API 키를 코드에 쓰지 않는다.** 환경변수나 별도 시크릿 저장소를 씁니다.
4. **소액으로 최소 3개월** 돌려 로그와 실제 체결을 대조합니다.
5. **킬 스위치**를 만든다. 한 번의 명령으로 전부 정지 가능해야 합니다.
6. **일일 최대 주문 금액 한도**를 코드에 박아둔다. 버그가 전 재산을 태우지 못하게.

`ccxt` 라이브러리로 연결할 수 있습니다. 필요하면 붙여드릴 수 있지만,
백테스트를 직접 돌려보고 규칙을 이해하기 전에는 권하지 않습니다.

## 파일 구조

```
systematic/
  config.py      규칙 — 모든 판단 기준이 여기 한 곳에
  data.py        Binance 공개 API + 로컬 캐시
  strategy.py    신호 산출과 목표 비중 계산
  schedule.py    '오늘 거래해도 되는 날인가' 판정
  backtest.py    백테스트 엔진 + 성과지표 + 벤치마크
run_rebalance.py 리밸런싱 실행기 (cron 대상)
run_backtest.py  백테스트 실행기
test_engine.py   엔진 검증 (합성 데이터, 네트워크 불필요)
```

### 엔진 검증

규칙을 바꾸거나 코드를 수정했다면 먼저 이걸 돌리세요. 네트워크 없이 즉시 끝납니다.

```bash
python test_engine.py
```

검증 항목: 리밸런싱 일정, 지표 계산, 레버리지/음수비중/종목상한 위반,
상장 전 자산 제외, **미래참조(look-ahead) 없음**, 거래 밴드 동작.

이 중 미래참조 검증이 가장 중요합니다. 미래 데이터를 잘라내고 다시 돌렸을 때
과거 구간 자산곡선이 완전히 동일해야 합니다. 다르다면 백테스트 결과는 전부 거짓입니다.

## 정직한 한계

이 시스템은 수익을 보장하지 않습니다. **감정에 의한 실수를 줄일 뿐입니다.**
그것만으로도 대부분의 개인 투자자에게는 큰 개선이지만, 다음은 분명히 알아야 합니다.

- **암호화폐 역사가 너무 짧습니다.** 의미 있는 사이클이 2~3개뿐이라
  백테스트의 통계적 신뢰도가 주식·채권 대비 현저히 낮습니다.
- **생존 편향이 있습니다.** BTC/ETH/XRP/SOL은 살아남은 종목입니다.
  2017년 시점에는 지금 사라진 코인들도 똑같이 유력한 후보였습니다.
- **추세추종은 횡보장에서 집니다.** 방향 없이 오르내리는 구간에서는
  고점에 사고 저점에 파는 일이 반복됩니다. 이건 버그가 아니라 이 전략의 구조적 대가입니다.
- **여전히 크게 잃을 수 있습니다.** 목표 변동성 연 40%는 주식 대비 매우 공격적입니다.
  30~50% 낙폭은 정상 범위 안에서 일어납니다.
- **규칙을 지키지 못하면 아무 소용 없습니다.** 이 시스템의 가치는 전부
  '폭락 중에도 규칙대로 실행하는 것'에 있습니다. 그때 규칙을 바꾸면 그냥 감으로 투자하는 겁니다.

잃어도 생활에 지장이 없는 금액만 투자하세요.
